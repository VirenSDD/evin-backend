# Proposal

## Why

The backend has no working tests: the 6 existing tests were generated by Rails when the controllers were created, call routes that do not exist, and rely on fixtures with columns that were removed. The GitHub Actions CI has failed in all three jobs since August 2026 and blocks nothing. Before refactoring the backend or adding new games, we need a safety net that catches any change in the current behavior of the API.

## What Changes

- Remove the Rails-generated tests and fixtures that test nothing (controllers, empty models, mailer and ActionCable).
- Make the CI work again:
  - the test job defines the database password required by `config/database.yml`, and stops installing Chrome and running system tests, which an API does not have;
  - Brakeman stops failing just because it is not the latest version (the `--ensure-latest` flag in `bin/brakeman`);
  - fix the 16 RuboCop style offenses.
- Add an integration test suite that exercises the API over HTTP, without depending on its internal structure, covering the happy path of every endpoint and its main errors (missing token, forbidden role, missing resource and invalid data).
- The specs in this change document the current API behavior as a baseline. No observable behavior changes.
- A set of authorization cases pending a security review is out of scope for this public change and will be handled privately with the project owners.

## Capabilities

### New Capabilities

- `authentication`: login, sign-up, own profile and password recovery.
- `game-catalog`: public listing of the game catalog.
- `student-management`: create, read, update, delete and statistics of students.
- `game-sessions`: recording and listing of played game sessions.
- `teacher-dashboard`: activity overview for professionals.
- `user-management`: account listing and role assignment by an administrator.

### Modified Capabilities

None: the project had no previous specs.

## Impact

- Test code: `test/` (fully replaced).
- Continuous integration: `.github/workflows/ci.yml` and `bin/brakeman`.
- Style: files with RuboCop offenses (quotes and whitespace only, no logic changes).
- Documentation: `README.md` with the steps to run the tests locally.
- No changes to the API, the database or the frontend.
